## 第 1 周:吃透现有项目(最重要)

| 天 | 任务 | 产出 |
|---|---|---|
| D1 | 跑 `python scorecard_pipeline.py`,对照 `REPORT.md` 看懂每个数字 | 能解释 AUC / KS / IV 分别是什么 |
| D2 | 精读 `load_data()`:为什么删 50% 缺失列?为什么 365243 要置空? | 自己改一次截尾分位(1%/99% → 5%/95%),看 AUC 变化 |
| D3 | 精读 `woe_table()`:**手算一个分箱的 WOE 和 IV**,和代码结果对照 | 一张手写计算纸 |
| D4 | 精读 `fit_logistic()`:理解 IRLS 为什么收敛快 | 用自己的话写出"逻辑回归在做什么" |
| D5 | 精读评分卡刻度:`FACTOR`、`OFFSET` 怎么来的,手算一个分箱分数 | 能解释"为什么 WOE 越高分越高" |
| D6 | 做 3 个参数实验:IV 阈值 0.01/0.02/0.05、分箱数 5/10/20、L2=0.1/1/10 | 一张参数对比表 |
| D7 | 复盘:把这一周学到的写成 500 字笔记 | 笔记 + 3 个新问题 |

**本周里程碑**:能脱离报告,自己讲清楚"这套评分卡是怎么做出来的"。

## 第 2 周:扩展多表特征(拉开差距)

- 读 `bureau.csv`:一个客户对应多条征信记录
- 做聚合特征:历史贷款笔数、逾期次数、平均逾期天数、当前在用贷款数
- 同理处理 `previous_application.csv`:历史申请次数、被拒次数
- 把新特征加入 `scorecard_pipeline.py`,重新训练
- 记录:**加特征前 vs 加特征后** 的 AUC 对比

**本周里程碑**:AUC 从 0.737 提升到 0.75+,并且有对比表。

> 提示:聚合时注意 `SK_ID_CURR` 主键关联,以及"只保留申请日之前的数据"避免穿越。

## 第 3 周:树模型对比 + 可解释性

- 用 `shap` 看特征重要性,和 IV 排序对比
- 写一段"为什么银行仍用评分卡(可解释性/监管)"的论述

**本周里程碑**:一张"逻辑回归 vs 树模型"对比表 + SHAP 图。
